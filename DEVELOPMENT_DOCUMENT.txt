1. Introduction
	Project Name: Atherluxia Hub
 Platform Type: Web Application
 Target Audience: Indie Game Developers, Players, and Enthusiasts
 Launch Date: TBD
 Version: 1.0 (Initial Development)

Overview
Atherluxia Hub is a community-driven platform designed to provide a launchpad for indie game developers to showcase their work, engage with their target audience, and receive valuable feedback that can drive further iteration and development. It operates similarly to Product Hunt but is specifically tailored to the indie game space, offering a dynamic environment for developers to present their projects, share updates, and receive real-time feedback from an engaged and enthusiastic community.
The platform aims to bridge the gap between indie game developers and gamers, creating a unique space where developers can connect directly with their users. Atherluxia Hub allows game creators to launch new titles, share progress updates, and build a community around their games. For players, it serves as a curated space to discover fresh indie titles, provide feedback, and support developers in their journey.

Mission Statement
Our mission is to empower indie game developers by providing a dedicated platform that fosters discovery, collaboration, and growth. Atherluxia Hub seeks to inspire creativity, provide transparency, and nurture relationships between developers and their community. By promoting indie games and supporting developers in their endeavors, we aim to cultivate a thriving ecosystem that encourages innovation and excellence in the gaming industry.

Key Features
Game Showcases: Developers can create detailed project pages to showcase their indie games with media, descriptions, and key features.


Community Interaction: Players and fellow developers can comment, upvote, and share their thoughts on each game, fostering engagement and feedback.


Voting & Ranking System: Community members can vote on games, giving rise to a daily or weekly leaderboard that showcases the most popular or promising games.


Developer Tools: Custom dashboards for developers to track user interactions, feedback, votes, and overall engagement with their projects.


Release Announcements: Developers can announce new releases, updates, and upcoming features, keeping their audience in the loop.


Search & Discovery: Players can browse games by category, genre, platform, or release date, making it easier to discover new indie titles.



Why Atherluxia Hub?
The indie game space is ever-expanding, and with the rise of crowd-sourced platforms, it is more crucial than ever for indie developers to carve out their own presence. Atherluxia Hub provides a focused environment that showcases indie games while fostering a sense of community. Unlike large platforms where indie titles may get lost among thousands of mainstream games, Atherluxia Hub offers tailored visibility for creators, giving them the tools they need to build meaningful relationships with their audience.
Our platform’s combination of community engagement, real-time feedback, and discovery mechanisms aims to offer developers not just a place to showcase their games but also a space to grow and iterate with the support of a like-minded community. For players, Atherluxia Hub becomes a go-to destination for discovering unique and innovative games that may not receive the same level of exposure on other, more mainstream platforms.

2. Platform Architecture & System Design
System Overview
Atherluxia Hub is designed as a scalable, modular platform built on modern web technologies, ensuring a smooth and responsive user experience. The system’s architecture is divided into multiple layers, each responsible for specific components of the platform’s functionality. This ensures the platform is maintainable, extensible, and capable of handling the evolving needs of its users.

High-Level Architecture
Atherluxia Hub’s architecture follows a layered approach, with distinct tiers for the frontend, backend, and data management:
Frontend (Client-Side):
 The frontend is built using modern JavaScript frameworks (React or Vue.js) and styled using Tailwind CSS to ensure a responsive and aesthetically pleasing design. The frontend communicates with the backend via RESTful APIs to retrieve and submit data.


Backend (Server-Side):
 The backend is powered by Flask, a lightweight Python web framework that provides flexibility and scalability. Flask is chosen for its simplicity and ease of integration with external APIs and services. The backend handles authentication, user data management, and the processing of game submissions and feedback.


Database:
 The platform utilizes PostgreSQL as the relational database management system, providing robust storage for user data, game details, votes, comments, and other key platform elements. PostgreSQL’s scalability and reliability make it ideal for handling large volumes of data.


Caching & Performance:
 To improve the performance and reduce latency, Redis is used for caching frequently requested data, such as game listings, votes, and community comments. This minimizes the load on the database and speeds up content delivery.


Media Storage:
 All game assets, including screenshots, videos, and downloadable files, are stored on a cloud-based file storage system, such as Amazon S3. This allows for easy scaling and ensures fast, reliable access to game media.


Authentication & Authorization:
 Users will authenticate via OAuth (e.g., Google, Facebook) or traditional email/password methods. The platform ensures secure user authentication with JWT (JSON Web Tokens) for session management and role-based access control (RBAC) to limit access to sensitive data.



System Components & Services
User Management Service
 Handles user registration, login, and profile management. It also supports social login integrations (Google, Facebook, etc.) and ensures secure password storage using bcrypt hashing.


Game Submission Service
 This service allows indie developers to submit their games for listing on the platform. The service includes form validation, file uploads for media assets, and automatic metadata extraction from the game files.


Voting & Ranking Service
 Responsible for managing votes from community members, updating the leaderboard rankings, and maintaining the integrity of voting data. This service prevents abuse such as fake votes and ensures only registered users can vote.


Commenting & Feedback Service
 A crucial service that allows users to leave comments, suggestions, and feedback on games. It supports real-time notifications to developers when feedback is left on their projects.


Notification Service
 This service manages email notifications, in-app alerts, and push notifications for key events, such as new votes, comments, or updates from developers on games they are following.


Search & Discovery Service
 Implements a fast and responsive search engine, enabling users to search for games by category, genre, platform, or keywords. This service utilizes Elasticsearch for full-text search and filtering capabilities.


Analytics & Reporting Service
 Provides detailed reports and dashboards for developers, showing metrics such as game performance, user engagement, votes, comments, and traffic sources. These insights help developers improve their games and marketing strategies.


Content Delivery Network (CDN)
 All static assets, such as images, JavaScript files, and CSS files, are served via a CDN to improve load times and ensure high availability.



Data Flow
User Journey:
 A typical user journey on Atherluxia Hub involves the following steps:


The user visits the homepage, where they can browse featured and new indie games.


They can log in using an account or sign up if they are new.


After logging in, they can interact with game listings by voting, commenting, or following their favorite games.


Developers can submit new games, track their game's progress via the dashboard, and respond to feedback.


Game Submission Flow:


A developer submits their game, filling out a submission form with basic game information (name, description, tags, etc.) and uploading media assets.


The backend validates the form and stores the game data in the database.


The game is then made live, and users can begin interacting with it.


Voting Flow:


Users vote for games they like.


Votes are recorded and stored in the database.


The leaderboard is updated accordingly, showing the most voted games.


Commenting Flow:


Users post comments or feedback on games.


The comment is stored in the database and associated with the correct game.


The developer is notified of new feedback via email or in-app alerts.



Scalability Considerations
The platform is designed to be scalable, accommodating future growth as more games are submitted and the user base expands. Key scalability features include:
Horizontal Scaling: The backend is designed to scale horizontally by adding more instances of the application server as demand increases.


Database Sharding: As the platform grows, the database can be partitioned across multiple servers, ensuring high availability and load distribution.


Content Delivery Network (CDN): By utilizing a CDN for static assets, Atherluxia Hub can serve users around the world with low latency and high availability.


3. Development Stack
Overview
Atherluxia Hub is built using a modern, scalable, and maintainable tech stack. The following describes the core technologies used in both the frontend and backend of the platform, along with their respective roles in the system. Each component was selected to ensure the platform is performant, secure, and flexible, enabling rapid development and future scalability.

Backend Technology
Flask (Web Framework)
 Flask is a lightweight Python web framework that serves as the core of Atherluxia Hub’s backend. Flask was chosen due to its simplicity, modularity, and ease of use, which makes it ideal for building RESTful APIs and managing user requests. Flask provides all the necessary tools for routing, middleware, and HTTP request handling, while allowing flexibility to integrate with other libraries for database management, authentication, and security.


Key Benefits:


Simple and lightweight: Minimal boilerplate code, allowing rapid development.


Extensible: Easily integrates with other services, including caching (Redis), database (MySQL), and external APIs.


Robust support for RESTful API design.


Flask-SQLAlchemy (ORM for Database Management)
 Flask-SQLAlchemy is an extension that integrates the SQLAlchemy ORM with Flask. It provides a high-level, Pythonic interface for interacting with the relational database, simplifying tasks such as querying, inserting, updating, and deleting records. Flask-SQLAlchemy also provides automatic schema migrations through Flask-Migrate, which helps in evolving the database schema as the platform grows.


Key Benefits:


Object-relational mapping: Allows developers to work with Python objects instead of raw SQL queries, reducing complexity.


Schema migrations: Easily manage database schema changes with version control.


Flexible querying: Supports complex queries and relationships between models.



Frontend Technology
Jinja2 (Template Engine)
 Jinja2 is a templating engine for Python used to dynamically generate HTML content. It is tightly integrated with Flask and allows for easy rendering of HTML pages. Jinja2 templates help separate the logic of data processing from the presentation layer, ensuring a cleaner, more maintainable codebase. Atherluxia Hub utilizes Jinja2 templates to render dynamic pages such as game listings, user dashboards, and submission forms.


Key Benefits:


Separation of concerns: Jinja2 helps maintain a clean separation between backend logic and frontend presentation.


Templating capabilities: Provides inheritance, control structures (loops, conditionals), and easy variable interpolation.


Flexibility: Easily integrates with Flask, enabling efficient page rendering.


base.html Layout Template
 The base.html template serves as the primary layout template for the frontend of Atherluxia Hub. It contains common structure elements that are reused across different pages, such as the navigation bar, footer, and meta tags. This layout template allows for consistency across the platform and helps avoid redundancy in the code.


Key Benefits:


Centralized structure: Reduces duplication and ensures a consistent look and feel across all pages.


Easy to extend: New pages can simply inherit from base.html, ensuring uniformity and ease of future updates.


TailwindCSS (Utility-First CSS Framework)
 TailwindCSS is a utility-first CSS framework that provides a set of low-level utility classes to build custom designs without having to write custom CSS from scratch. It allows developers to design highly responsive, modern layouts with minimal effort. TailwindCSS is integrated into the platform to create a responsive, visually appealing, and user-friendly interface for both desktop and mobile devices.


Key Benefits:


Flexibility: Allows for rapid UI development and customization.


Responsiveness: Built-in utilities make it easy to create responsive layouts across different screen sizes.


Efficiency: Reduces the need to write custom CSS, leading to cleaner code and faster development.



Database Technology
MySQL (Relational Database Management System)
 MySQL is the relational database management system (RDBMS) used to store and manage data for Atherluxia Hub. MySQL was selected for its scalability, reliability, and extensive support within the Python ecosystem. It provides a robust system for handling complex queries, relational data, and ensuring data integrity across the platform.


Key Benefits:


Scalability: MySQL can handle large datasets and support growth as Atherluxia Hub’s user base expands.


Performance: Optimized for high-speed query execution and efficient data storage.


ACID compliance: Ensures that all database transactions are processed reliably and consistently.


Database Schema Overview:
 The database schema is designed to store key entities such as users, games, votes, comments, and game submissions. Tables are structured with relationships to ensure that the platform’s core functionality, such as user interaction with games, can be efficiently managed. Primary entities and relationships include:


Users: Stores user profile information, including authentication credentials, preferences, and activity.


Games: Stores game details, such as title, description, media links, category, and developer info.


Votes: Tracks user votes on games, ensuring that votes are stored efficiently and counted for leaderboard rankings.


Comments: Stores user feedback and comments related to specific games, allowing for developer responses.


Submissions: Stores information about game submissions, including metadata, media uploads, and submission timestamps.



Additional Technologies
Redis (Caching Layer):
 Redis is employed to cache frequently accessed data such as game listings, leaderboard rankings, and user data. By reducing the load on the MySQL database, Redis helps maintain fast response times and improves the overall performance of the platform.


Celery (Asynchronous Task Queue):
 Celery is used to handle background tasks such as sending notifications, processing file uploads, and handling time-consuming operations like image resizing or media processing. Celery ensures that these tasks do not block the main application’s request-response cycle, allowing for a smooth user experience.


JWT (JSON Web Tokens):
 JSON Web Tokens (JWT) are used for secure user authentication and authorization. JWTs are passed between the frontend and backend to ensure that users are authenticated for protected routes and actions. The use of JWT allows for stateless authentication, meaning there is no need to store session data on the server.



Integration with Third-Party Services
Atherluxia Hub integrates with several third-party services to enhance the platform’s functionality:
OAuth Providers (Google, Facebook):
 Users can sign up or log in using their Google or Facebook accounts, making the registration process faster and more convenient.


Cloud Storage (Amazon S3):
 All media assets, such as images and videos, are stored on Amazon S3 for reliable and scalable storage. This ensures that game developers can easily upload and manage large media files.


SendGrid (Email Notifications):
 SendGrid is used for sending email notifications to users, such as confirmation emails, game updates, and notifications about new feedback or votes.

5. Security & Best Practices
Overview
Security is a critical component of Atherluxia Hub. Given the nature of the platform, which facilitates user interactions, game submissions, votes, and comments, ensuring data privacy, secure user authentication, and protection from malicious activity is paramount. This section outlines the platform's security architecture, key practices, and guidelines for developers to follow when working with the platform.

Authentication and Authorization
JSON Web Tokens (JWT)
 Atherluxia Hub uses JSON Web Tokens (JWT) for stateless authentication. After a user logs in, a JWT is generated and returned to the client. This token is then included in subsequent API requests to verify the user’s identity. JWTs are stored securely on the client-side (usually in HTTP-only cookies or local storage).


JWT Expiration: Tokens have an expiration time (e.g., 1 hour), after which the user must log in again to receive a new token. This helps mitigate the risk of token theft.


Secure Storage: For frontend security, store JWTs in HTTP-only cookies to prevent cross-site scripting (XSS) attacks.


Token Refresh: Implement a token refresh strategy for longer user sessions. When the token expires, the client can request a new token using a refresh token, which also has an expiration time.


OAuth Authentication
 To allow users to authenticate using third-party services (such as Google or Facebook), OAuth 2.0 is employed. OAuth reduces friction for users while maintaining secure login procedures. When implementing OAuth, ensure that:


Access tokens are securely stored and never exposed to the frontend.


OAuth tokens are validated before granting access to the user’s account data.


Role-based Access Control (RBAC)
 Although Atherluxia Hub’s current user roles are limited to general users and developers, the platform is designed to allow the easy addition of more roles in the future. Access to certain resources (e.g., game submission, admin settings) is controlled through role-based access policies.



Data Protection & Encryption
Encryption at Rest
 All sensitive data stored in the database, including user passwords and game-related media, is encrypted at rest. For passwords, a strong hashing algorithm (e.g., bcrypt) is used, ensuring that even if the database is compromised, password information cannot be easily recovered.


Encryption in Transit
 The platform uses TLS/SSL encryption to secure all data transmitted between clients and the server. This protects user data, such as passwords and personal information, from interception during transmission.


Ensure that the server forces HTTPS connections by redirecting all HTTP requests to HTTPS.


Use certificates from a trusted Certificate Authority (CA) to avoid man-in-the-middle (MITM) attacks.



Database Security
SQL Injection Prevention
 SQL injection attacks are one of the most common threats to web applications. To prevent SQL injection:


Use an ORM like SQLAlchemy to abstract SQL queries and avoid directly writing raw SQL queries.


Always use parameterized queries when interacting with the database to ensure that user input is treated as data, not executable code.


Database Access Control
 Ensure that access to the database is restricted based on the principle of least privilege. Database accounts should only have the permissions necessary to perform their specific tasks, reducing the impact of potential security breaches.



User Data Privacy
Personal Data Minimization
 Atherluxia Hub aims to collect the minimal amount of personal data necessary for user registration and interaction. This includes:


Email address (for authentication and communication).


Display name (for personalization).


Profile picture (optional).


Avoid storing unnecessary sensitive data, such as payment information, unless required by specific features. When possible, integrate with third-party services for payments or subscriptions (e.g., Stripe, PayPal) to offload sensitive financial data handling.


Privacy Settings
 Users have the option to configure their privacy settings. For example, they can:


Control who can view their profile information.


Control the visibility of their comments and game votes.


Choose whether they want to receive email notifications.



Best Practices for API Integration
Rate Limiting
 To prevent abuse and ensure fair use of API resources, Atherluxia Hub employs rate limiting. This limits the number of API requests that can be made by a user within a specific time frame (e.g., 100 requests per hour).


Rate limiting helps protect the platform from DDoS attacks and ensures that system resources are distributed fairly.


API Throttling
 In addition to rate limiting, API throttling is used to control the flow of requests to prevent server overload. Throttling involves slowing down requests if the system detects that too many requests are being made in a short time span.


Input Validation and Sanitization
 Every incoming API request should be validated to ensure that the data is in the correct format and within the expected range. This includes:


Ensuring that all user inputs (e.g., names, email addresses, and comments) are properly sanitized to avoid XSS (cross-site scripting) and other injection attacks.


Using libraries and frameworks that automatically sanitize data, such as Flask-WTF for form validation and SQLAlchemy for ORM-driven data validation.


CORS (Cross-Origin Resource Sharing) Policies
 Atherluxia Hub implements strict CORS policies to ensure that API requests are only accepted from trusted origins. This prevents unauthorized websites from making API requests to the platform on behalf of users, protecting against cross-site request forgery (CSRF) attacks.



Secure Media Handling
File Upload Security
 Atherluxia Hub allows users to upload media files (e.g., screenshots, game videos). To secure file uploads:


Only allow specific file types (e.g., .jpg, .png, .mp4) to prevent malicious files (e.g., executables) from being uploaded.


Perform virus scanning on all uploaded files using services like ClamAV or integrate with a third-party security service.


Limit file size to prevent denial of service (DoS) attacks that exploit large file uploads.


Storage and Access Control
 Media files are stored securely on Amazon S3, and access to these files is controlled using secure access keys. Ensure that access to media files is granted only to users who have permission to view or modify them.



Handling Security Vulnerabilities
Regular Security Audits
 Atherluxia Hub conducts regular security audits to identify and address potential vulnerabilities. These audits involve both automated scanning tools and manual code reviews. Critical security patches are promptly applied.


Bug Bounty Program
 Atherluxia Hub encourages ethical hacking and offers rewards for discovering vulnerabilities in the system. The bug bounty program helps ensure that any potential security issues are identified and resolved before they can be exploited.


Logging and Monitoring
 All system activities, such as login attempts, file uploads, and database queries, are logged to a centralized logging system. This helps identify suspicious activity and allows the security team to respond swiftly in case of a breach.



Security Recommendations for Developers
Use Secure Passwords: When setting passwords for your local development environment or production servers, use a password manager to generate and store strong passwords.


Do Not Expose Sensitive Information: Always make sure that sensitive information (such as API keys, database credentials, etc.) is not exposed in public repositories or frontend code. Use environment variables and encrypted storage for these credentials.


Use HTTPS Everywhere: Ensure that all communication with the API is done over HTTPS. Do not expose any unencrypted endpoints.



6. Deployment & Scaling

Overview
In this section, we will detail the deployment strategies, environment setup, and scaling practices for Atherluxia Hub. Given the dynamic nature of the platform, it is important to ensure that it can scale effectively to handle growth in user base and game submissions while maintaining high performance and availability. This page covers the best practices for deploying Atherluxia Hub to production, managing environment variables, and scaling the system as demand increases.

Production Environment Setup
Atherluxia Hub is designed to be deployed on cloud services such as AWS, Google Cloud, or any other cloud platform with infrastructure-as-a-service (IaaS) capabilities. Below is an outline of the environment setup for deploying Atherluxia Hub:
Web Server (Gunicorn)
 Atherluxia Hub uses Gunicorn as the WSGI HTTP server to serve the Flask application. Gunicorn is a robust choice for serving Python web applications, as it is compatible with multi-threaded and multi-process configurations.

 Configuration:


Number of workers: The number of Gunicorn workers should be based on the number of CPU cores available on the server (e.g., workers = 2 * CPU + 1).


Binding: Bind Gunicorn to the appropriate socket or IP address.


Timeout: Set appropriate timeouts to prevent long-running requests from hanging indefinitely.


Example Gunicorn command for launching the application:

 bash
CopyEdit
gunicorn -w 4 -b 0.0.0.0:8000 app:app


Reverse Proxy (Nginx)
 Nginx will act as a reverse proxy to handle incoming requests and forward them to the Gunicorn application. Nginx also provides SSL termination, load balancing, and can serve static assets directly to reduce the load on Gunicorn.

 Configuration:


Set up SSL/TLS using Let's Encrypt or a commercial certificate to ensure all traffic is encrypted.


Use Nginx to forward requests to Gunicorn, ensuring that the Flask application is behind a secure proxy.


Example Nginx configuration:

 nginx
CopyEdit

8: Date Models Documentation
Overview
The foundation of Atherluxia Hub's platform is built upon well-defined data models that reflect the platform’s functionality. These models represent key entities, their relationships, and interactions. This section describes the data models that will be implemented in the backend, how they relate to each other, and how they will support the features of the platform.

1. User Model
The User model represents a platform user and holds important details such as authentication information, profile data, and associated roles.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each user.


username: String (Unique)
 The unique username for the user, chosen by the user during registration.


email: String (Unique)
 The user's email address for communication and authentication.


password_hash: String
 A hashed version of the user's password.


role: Enum (Choices: 'admin', 'developer', 'user')
 The role of the user within the platform, determining access and privileges.


bio: String (Optional)
 A short user bio for personalization.


profile_picture_url: String (Optional)
 URL to the user's profile picture.


created_at: DateTime
 The date and time the user account was created.


updated_at: DateTime
 The date and time the user's information was last updated.


Relationships:


A User can submit multiple games (Game model).


A User can cast multiple votes (Vote model).



2. Game Model
The Game model represents a game project that has been submitted by a developer to Atherluxia Hub. This model contains detailed information about the game, such as its title, description, genre, and media assets.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each game.


title: String (Required)
 The title of the game.


description: Text
 A detailed description of the game, outlining its mechanics, objectives, and gameplay features.


developer_id: Integer (Foreign Key to User.id)
 The ID of the user who submitted the game.


genre: String
 The genre of the game (e.g., Action, Adventure, RPG, etc.).


platforms: String
 A list of platforms the game is available on (e.g., PC, Web, Console).


cover_image_url: String (Optional)
 URL to the cover image of the game.


release_date: DateTime (Optional)
 The scheduled release date for the game, if applicable.


status: Enum (Choices: 'pending', 'approved', 'rejected')
 The current status of the game on the platform (whether it's under review, approved for listing, or rejected).


created_at: DateTime
 The date and time the game was submitted to Atherluxia Hub.


updated_at: DateTime
 The date and time the game's information was last updated.


Relationships:


A Game is submitted by one User (developer).


A Game can receive multiple Vote entries from users.


A Game can have multiple Comment entries from users.



3. Vote Model
The Vote model represents a user's vote on a particular game. Votes help determine which games rise in visibility and which games are favored by the community.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each vote.


user_id: Integer (Foreign Key to User.id)
 The ID of the user who cast the vote.


game_id: Integer (Foreign Key to Game.id)
 The ID of the game that the user voted for.


vote_type: Enum (Choices: 'upvote', 'downvote')
 The type of vote (upvote for favoriting a game, downvote for disliking a game).


created_at: DateTime
 The date and time the vote was cast.


Relationships:


A Vote is cast by one User.


A Vote is cast on one Game.



4. Comment Model
The Comment model allows users to add comments to games. This facilitates discussion and feedback around games, encouraging community engagement.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each comment.


user_id: Integer (Foreign Key to User.id)
 The ID of the user who wrote the comment.


game_id: Integer (Foreign Key to Game.id)
 The ID of the game the comment is associated with.


content: Text
 The content of the comment.


created_at: DateTime
 The date and time the comment was made.


Relationships:


A Comment is written by one User.


A Comment belongs to one Game.



5. Tag Model
The Tag model is used to categorize games by specific keywords or topics, making it easier for users to discover games of interest. Tags can be assigned to multiple games.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each tag.


name: String (Unique, Required)
 The name of the tag (e.g., 'Action', 'Indie', 'Multiplayer').


created_at: DateTime
 The date and time the tag was created.


Relationships:


A Tag can be associated with many Game entries (many-to-many relationship).



6. Notification Model
The Notification model stores notifications that are sent to users regarding important events, such as game approval, vote status updates, or new comments on their games.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each notification.


user_id: Integer (Foreign Key to User.id)
 The ID of the user receiving the notification.


message: String
 A brief description of the notification (e.g., "Your game has been approved!").


read: Boolean
 Indicates whether the user has read the notification.


created_at: DateTime
 The date and time the notification was created.


Relationships:


A Notification is sent to one User.



7. Follow Model
The Follow model allows users to follow other users, which could be particularly useful for developers to track other developers, influencers, or favorite games.
Attributes:


id: Integer (Primary Key)
 A unique identifier for each follow.


follower_id: Integer (Foreign Key to User.id)
 The ID of the user who is following another user.


followed_id: Integer (Foreign Key to User.id)
 The ID of the user who is being followed.


Relationships:


A Follow is created by one User who follows another User.
